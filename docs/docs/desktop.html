Desktop app

portop desktop shows the same information as the terminal UI in a window, with dev servers, a connection map, an activity log and a tray menu. It is a separate download; the portop command does not change.

Install

SystemPackageRequires
Ubuntu, Debiansudo apt install portop-desktop from the APT repository, or the portop-desktop_*_linux_amd64.deb from the releaseUbuntu 24.04+, Debian 13+ (GTK4 and WebKitGTK 6, installed as dependencies)
Fedora, RHELportop-desktop_*_linux_amd64.rpm from the release: sudo dnf install ./portop-desktop_*.rpmFedora 40+ (GTK4 and WebKitGTK 6)
macOSportop-desktop_*_macos_universal.zip: unzip and move portop.app to ApplicationsmacOS 12+, Intel or Apple Silicon
Windowsportop-desktop_*_windows_amd64.zip or _arm64.zip: unzip and run portop-desktop.exeWindows 10 or 11 with the WebView2 runtime (included in both)

Downloads are on the latest release, with checksums in portop-desktop_checksums.txt and build provenance you can check with gh attestation verify FILE --repo padovanl/portop.

macOS first launch

The app is not notarized, so macOS refuses to open it the first time. Right-click portop.app, choose Open, then Open again; or run xattr -dr com.apple.quarantine /Applications/portop.app.

Older Linux releases

Ubuntu 22.04 and Debian 12 do not ship WebKitGTK 6, which the app needs. On them, portop --web gives the same information in a browser, and the terminal UI works as before. Linux on ARM gets the terminal UI and the web dashboard; the desktop app is built for x86-64 only.

Views

Overview
Counters for listening ports, dev servers, exposed ports and live traffic; warnings for exposed ports, changes since the baseline and hidden owners; a card for each dev server with its project, framework, ports and traffic; the other services (databases, web servers, containers, system services).
Ports
Every socket, filtered by state (listening, connected, all), category, at risk, or any text (port, process, project, address). Pin ports to keep them on top, watch them to be notified when they open or close, and export what is shown.
Connections
A service map: every process is a card, and an arrow goes from a client to the server it uses, with the traffic between them. Cards fall into columns by role (entry points, applications, their dependencies, remote hosts); processes that talk to no other process are listed underneath. Hover a card to follow its links, search to highlight, and pause to study a moment.
Projects
Recent projects, started again with one click, and the Docker Compose check.
Activity
Listening ports that opened or closed since the app started, the watched ports and the baseline. Relevant, the default, applies the notification filters; Everything shows every event. Each entry can mute its process.
Settings
Theme, refresh interval, the administrator view, start at login, the global shortcut, the editor, notifications and their filters, muted processes, other machines, keeping the app in the tray, and reduced motion.

Icons

A program and a project each have an icon. In the ports table the Process column shows the program's (node, nginx, Chrome) and the Project column the project's; dev server cards and the connections map show the project's when there is one.

  • A program's icon is its own when the system has one (the .desktop entry's on Linux, the app bundle's on macOS, the one inside the .exe on Windows); otherwise a bundled logo found by its name: runtimes (node, python, java, php, ruby, dotnet…), servers and databases that ship no icon (nginx, Apache, Caddy, PostgreSQL, MySQL, MongoDB, Redis, Kafka, Elasticsearch, Grafana, Docker…), editors (VS Code, JetBrains IDEs, Cursor, Zed, Neovim…) and common apps (Chrome, Firefox, Spotify, Discord, Slack, Steam…); for a script, its interpreter's language.
  • A project's icon is its favicon or logo (favicon.svg, public/favicon.png, static/logo.svg and similar), otherwise its framework's logo (Vite, Next.js, Django, Rails, Laravel…), otherwise its language's.

Anything else gets a colored monogram. The logos come with the app, about 180 of them, from Devicon (MIT) and Simple Icons (CC0), so nothing is downloaded and no one learns what runs on your machine. The names and logos belong to their owners; scripts/gen-logos.py lists them all.

Process details

Click any row or card for the details: command line, working directory, user, start time, CPU and memory, the process's sockets, and its traffic over the last minutes or the last hour (3 min and 1 h above the chart; the hour is kept in 30-second points while the app runs). From there you can open its folder or project, open it in your editor, restart it, or stop it.

Stopping and restarting

Stop sends SIGTERM and Force kill sends SIGKILL; Windows has no SIGTERM, so there both end the process at once. Both need the button held for a moment, and both check that the process still has the start time the app read, so a PID reused by another program is never signalled. Stop all above the dev server cards stops every dev server the same way.

A process of another user (root, a service account) is stopped through your system's administrator prompt: pkexec on Linux, the password dialog on macOS, UAC on Windows. The prompt runs portop-desktop --signal-pid, which repeats the start-time check as administrator. With the administrator view on, no prompt is shown again.

Restart is offered for your own processes whose command and directory portop can read: it stops the process, waits for it to exit, and runs the same command from the same directory in a new terminal window, where its output and errors stay visible.

Free a port, at the top of the overview, takes a port number, shows who holds it and stops it; it also lists the next free ports above it, ready to copy.

Projects and your editor

Every dev server portop sees is remembered with its folder and the command that started it, up to 40 of them. In Projects, a stopped one starts again with Start, in a new terminal window, from the same folder and with the same command; Forget removes it. The list is kept in desktop-recent.json next to the settings, readable by you only.

Open in editor, on dev server cards, recent projects and process details, opens the project folder in the editor chosen in Settings, or the first one found: VS Code, Cursor, Windsurf, Zed, Sublime Text, JetBrains IDEs or VSCodium. Other command… takes any command that opens a folder given as its last argument.

Docker Compose

Check a Compose project… reads a project's compose files, as portop --compose does, and lists each published port: listening as expected, taken by another program, or not listening. Projects checked before are a click away.

Containers

A port that belongs to a container shows a box button. It opens the container: Start, Stop and Restart (through the Docker or Podman API; stopping and restarting ask to hold the button), and its last 300 lines of output. The button is hidden when no container engine answers.

Exposed ports

A dev server, database or container that listens on every interface (or on a network address) and that the firewall does not block can be reached from the network, which is usually a mistake: a database bound to 0.0.0.0 during development, say. Such ports are marked at risk, listed above the overview, and, with Warn about exposed ports on, notified once when they appear. Web servers are left out: they are meant to be reachable.

Baseline

The baseline is the set of listening ports you expect, the same file portop --save-baseline and --diff use. Save current ports as baseline, in Activity, records it; from then on the overview says how many ports were added or have gone, and Activity lists them.

Export

Export JSON and CSV, in Ports, save the sockets as a file: JSON with the fields of portop --json, CSV for a spreadsheet (values that a spreadsheet would read as a formula are escaped).

Other machines

The window can show the ports of another machine that runs portop --web --web-auth. Add it in Settings with a name, its address and user; choose it in the machine menu at the top left, type the dashboard password, and the views show that machine, read only. The password stays in memory until the app quits and is never saved.

An address with https:// must have a certificate this system trusts. A self-signed one shows its SHA-256 fingerprint; compare it with the one the server printed and trust it, and the app checks that exact certificate from then on.

Tray

The tray icon (the menu bar on macOS) lists the running dev servers, each with Open in browser and Stop, which asks for confirmation, and Start a recent project. Closing the window keeps portop in the tray unless Keep running in the tray is off.

Start at login and global shortcut

Start at login starts portop in the tray when you sign in (a login item on macOS, an autostart entry on Linux, the Run key on Windows). The global shortcut shows the window and its port finder from any app. Wayland gives applications no global shortcuts, so on a Wayland session the setting is hidden; under X11 it works.

Notifications

Notifications use the system's own: notify-send on Linux, Notification Center on macOS, toasts on Windows.

  • Watched ports notify at once, when they open and when they close. Add them in Activity, or with the bell on a row of Ports.
  • New ports notify only when Notify about new ports is on, and only if the port is still open five seconds later, is in one of the chosen categories (dev servers, databases, web servers and containers by default), is TCP unless Include UDP ports is on, and does not belong to a muted process.

Why the defaults

Browsers, video calls and music players open and close short-lived ports, mostly UDP, many times a minute. Leaving out apps, system services and UDP keeps notifications to the ports you start yourself. If one program still gets through, mute it from its entry in Activity.

Administrator view

The app runs as your user. Like portop without sudo, it then sees every port but not which process owns the sockets of root, services and other users, nor their details; those show as hidden, and the overview groups them in one tile.

Show all, in Settings or on the overview's warning, asks for the administrator password once and then shows every process with its details, and stops other users' processes without asking again. The window itself never runs as administrator, which a web view should not do: it starts portop's helper instead (the same executable, with --elevated-helper), through pkexec on Linux, the password dialog on macOS or UAC on Windows. The helper scans and answers the window only, on a loopback port behind a random token written to a folder only you can read. Administrator view · Stop, in the sidebar, ends it; it also ends when portop quits.

Already running as administrator

Started with Run as administrator on Windows, portop sees everything from the start and Settings says so. On Linux and macOS, use Show all rather than starting the app with sudo.

Features your system lacks

The app checks what works where it runs and hides what cannot: container buttons without a Docker or Podman engine, Restart and Start without a terminal to open, the global shortcut on Wayland, Show all on Linux without pkexec. When a feature is missing for a reason you can fix, Settings says so; when you view another machine, actions that only make sense on this one are hidden.

Settings and data

Preferences are saved in desktop.json next to config.yml, and recent projects in desktop-recent.json, both readable by your user only. The page is built into the executable and its Content-Security-Policy allows no outside resources. The app connects only to machines you add under other machines, to your container engine, and to addresses of this machine when you open one.

Built with Wails v3

The app uses Wails v3, which is in beta; portop pins one release and updates it deliberately. The scanning code is the same as the terminal UI's.
