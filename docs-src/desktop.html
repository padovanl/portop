Desktop app

portop desktop shows the same information as the terminal UI in a window, with dev servers, a connection map, an activity log and a tray menu. It is a separate download; the portop command does not change.

macOS first launch

The app is not notarized, so macOS refuses to open it the first time. Right-click portop.app, choose Open, then Open again; or run xattr -dr com.apple.quarantine /Applications/portop.app.

Older Linux releases

Ubuntu 22.04 and Debian 12 do not ship WebKitGTK 6, which the app needs. On them, portop --web gives the same information in a browser, and the terminal UI works as before. Linux on ARM gets the terminal UI and the web dashboard; the desktop app is built for x86-64 only.

Views

Overview
Counters for listening ports, dev servers, exposed ports and live traffic; a card for each dev server with its project, framework, ports and traffic; the other services (databases, web servers, containers, system services). Type a port in Free a port to see its owner and stop it.
Ports
Every socket, filtered by state, category or any text (port, process, project, address). Pin ports to keep them on top, or watch them to be notified when they open or close.
Connections
A service map: every process is a card, and an arrow goes from a client to the server it uses, with the traffic between them. Cards fall into columns by role (entry points, applications, their dependencies, remote hosts); processes that talk to no other process are listed underneath. Hover a card to follow its links, search to highlight, and pause to study a moment.
Activity
Listening ports that opened or closed since the app started, and the list of watched ports. Relevant, the default, applies the notification filters; Everything shows every event. Each entry can mute its process.
Settings
Theme, refresh interval, notifications and their filters, muted processes, keeping the app in the tray, and reduced motion.

Ctrl+K (⌘+K on macOS) finds a port from anywhere; / jumps to the port filter; 1 to 5 switch views.

Stopping and restarting

Stop sends SIGTERM and Force kill sends SIGKILL; Windows has no SIGTERM, so there both end the process at once. Both need the button held for a moment, and both check that the process still has the start time the app read, so a PID reused by another program is never signalled.

A process of another user (root, a service account) is stopped through your system's administrator prompt: pkexec on Linux, the password dialog on macOS, UAC on Windows. The prompt runs portop-desktop --signal-pid, which repeats the start-time check as administrator. The window itself never runs elevated.

Restart is offered for your own processes whose command and directory portop can read: it stops the process, waits for it to exit, and runs the same command from the same directory in a new terminal window, where its output and errors stay visible.

Tray

The tray icon (the menu bar on macOS) lists the running dev servers, each with Open in browser and Stop, which asks for confirmation. Closing the window keeps portop in the tray unless Keep running in the tray is off.

Notifications

Notifications use the system's own: notify-send on Linux, Notification Center on macOS, toasts on Windows.

  • Watched ports notify at once, when they open and when they close. Add them in Activity, or with the bell on a row of Ports.
  • New ports notify only when Notify about new ports is on, and only if the port is still open five seconds later, is in one of the chosen categories (dev servers, databases, web servers and containers by default), is TCP unless Include UDP ports is on, and does not belong to a muted process.

Why the defaults

Browsers, video calls and music players open and close short-lived ports, mostly UDP, many times a minute. Leaving out apps, system services and UDP keeps notifications to the ports you start yourself. If one program still gets through, mute it from its entry in Activity.

What the app can see

The app runs as your user. Like portop without sudo, it sees every port but not which process owns the sockets of other users on Linux; those show as hidden, and the overview groups them in one tile. Project detection reads your own processes' working directories only.

Settings and data

Preferences are saved in desktop.json next to config.yml, readable by your user only. The app makes no network connections of its own: the page is built into the executable, its Content-Security-Policy allows no outside resources, and Open in browser only opens addresses of this machine.

Built with Wails v3

The app uses Wails v3, which is in beta; portop pins one release and updates it deliberately. The scanning code is the same as the terminal UI's.
